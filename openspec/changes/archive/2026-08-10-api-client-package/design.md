# Design: api-client-package — types-only `@moneydiary/api-client`, no build step

> SDD design artifact. Hybrid store — mirror of Engram topic `sdd/api-client-package/design`.
> Reads from `proposal.md` + `explore.md` (same folder) and `docs/adr/ADR-012-packages-api-client.md`.
> This is the HOW at architectural level: package anatomy, codegen pipeline, CI gates, per-DTO adoption
> mapping, mobile mechanics, ADR amendment intent, slice sketch. Not the spec, not the task list, not code.
>
> **Settled upstream, not reopened here:** types-only first slice (explore Option B); `types.gen.ts` is
> **committed**; no `tsup`/build step; delivery `ask-on-risk`.

## Decision (lead)

**`packages/api-client` ships as a source-only TypeScript package with a hand-curated alias layer
(`src/index.ts`) on top of the generated `src/types.gen.ts`, and the alias layer is IN SCOPE.**

The alias layer is the decision worth defending, because "just export `components`" looks simpler:

- **DRY.** The mapping *"the wire schema `ResumenMesResponse` is what both apps call `ResumenMesDto`"* is one
  piece of knowledge. Without an alias layer it gets written **twice** (once in `apps/web/src/api/types.ts`,
  once in mobile), and the deep indexed-access forms are worse — `DetalleBucketTransaccionDto` is
  `components['schemas']['DetalleBucketResponse']['transacciones'][number]`, an expression no one should
  retype per app. Five of the fifteen adopted types are indexed accesses into an array item.
- **KISS at the call site.** Every existing consumer (`use-resumen.ts`, `capabilities.ts`,
  `require-session.ts`, 20+ files) already imports `import type { ResumenMesDto } from './types'`. With the
  alias layer, `apps/web/src/api/types.ts` becomes a re-export barrel and **not one consumer file changes**.
  Without it, every consumer either renames its import or the app writes the aliases anyway.
- **YAGNI boundary.** The layer is *only* type aliases + the existing "why" comments. No runtime, no
  helpers, no re-derived shapes. It is ~60 lines that delete ~300 lines of hand-typed structure.

**What the layer must never do:** re-declare a field, widen/narrow a shape, or "fix" the contract. Every
alias is a one-line indexed access into `components['schemas']`. A mismatch with an app's expectation is
resolved **in the app**, never by editing the alias — otherwise the package becomes a second hand-written
mirror and the whole change is pointless.

## Package anatomy

```
packages/api-client/
├── package.json          ← name @moneydiary/api-client, private, types/exports → source
├── tsconfig.json         ← strict, noEmit; only powers the package's own `typecheck`
└── src/
    ├── types.gen.ts      ← GENERATED by openapi-typescript · COMMITTED · never edited by hand
    ├── index.ts          ← public surface: re-export `paths`/`components` + the DTO alias layer
    └── money-contract.assert.ts  ← compile-time assertions pinning money fields to `string`
```

No `openapi.json` copy inside the package (ADR-012's original layout put one there). The source of truth
stays `apps/api/openapi.json` (ADR-011 amend) and the generator reads it by relative path — two committed
copies of the same document would be a DRY violation with no gate keeping them equal.

### `package.json`

| Field | Value | Why |
|---|---|---|
| `name` | `@moneydiary/api-client` | ADR-012 |
| `private` | `true` | never published; internal `workspace:*` (ADR-012, `release-please-config.json` has no entry and needs none) |
| `version` | `0.1.0` | inert (no release-please component); present so pnpm is happy |
| `type` | `module` | repo default for TS workspaces |
| `types` | `./src/index.ts` | fallback for `moduleResolution: node10/node16` consumers |
| `exports` | `{ ".": { "types": "./src/index.ts" } }` | **`types` condition only — deliberately NO `default`/`import` runtime entry** |
| `scripts.generate` | `openapi-typescript ../../apps/api/openapi.json --immutable --output ./src/types.gen.ts` | the whole pipeline |
| `scripts.typecheck` | `tsc --noEmit` | compiles `src/`, which is what makes `money-contract.assert.ts` a real gate |
| `devDependencies` | `openapi-typescript` (exact pin), `typescript` | no `tsup`, no `openapi-fetch` — no runtime |

**The missing runtime entry is a feature, not an omission.** A types-only package must never be resolved at
runtime. If someone writes `import { algo } from '@moneydiary/api-client'` (a value import), resolution
fails loudly at build time instead of silently dragging a `.ts` file into Metro's or Vite's graph. That
loud failure is the guardrail that keeps this slice types-only until the real client lands. Consequence to
accept: the spike (below) must confirm nothing in mobile's toolchain *eagerly* resolves the runtime
condition of a declared dependency.

**No `main`, no `dist`, no `build` script.** Consumers compile the source. This is the proposal's decision
#1 (`tsup` exists to ship *runtime* code to two bundlers; there is none). It removes a dependency, an
artifact, and a build-ordering edge from CI.

### `tsconfig.json`

Standalone (the repo has no shared TS base config — creating one is out of scope and would touch four
workspaces):

```jsonc
{
  "compilerOptions": {
    "strict": true, "noEmit": true,
    "target": "es2023", "module": "esnext", "moduleResolution": "bundler",
    "skipLibCheck": true, "types": []
  },
  "include": ["src"]
}
```

`"types": []` keeps ambient `@types/*` out — the package must compile with zero platform assumptions (no
DOM, no Node, no RN), which is ADR-012's agnosticism constraint made mechanical.

### `src/index.ts` — the alias layer (shape, not final text)

```ts
export type { paths, components, operations } from './types.gen';
import type { components } from './types.gen';
type S = components['schemas'];

/** GET /api/resumen — 50/30/20 monthly breakdown. Money as decimal strings (BigInt-safe). */
export type ResumenMesDto = S['ResumenMesResponse'];
export type BucketResumenDto = S['ResumenMesResponse']['buckets'][number];
// … 13 more, one line each
```

`paths`/`components` stay exported: the future runtime client needs `paths`, and an app that wants a shape
the alias layer does not name can index directly without a package change.

## Codegen pipeline

```
apps/api/src/.../schemas/*.schema.ts   (Zod — single source of truth, ADR-011)
        │  pnpm api openapi:emit          [gate: pnpm api openapi:check]
        ▼
apps/api/openapi.json                  (committed)
        │  pnpm api-client generate      [gate: regenerate + git diff --exit-code]
        ▼
packages/api-client/src/types.gen.ts   (committed)
        │  import type
        ▼
apps/web  ·  apps/mobile               [gate: tsc --noEmit in each app's CI job]
```

Three links, three gates, no orchestrator (ADR-012 defers Turborepo explicitly). A root convenience script
`"contract:sync": "pnpm api openapi:emit && pnpm api-client generate"` encodes the chain order in the one
place a human will look for it, plus root shortcut `"api-client": "pnpm --filter @moneydiary/api-client"`
for symmetry with `api`/`web`/`landing`.

### Generator version (quarantine-aware)

`openapi-typescript` **exact pin, no caret** — the generator version is a determinism input, same
discipline as `zod-openapi@5.4.2` in the contract change.

This design does **not** hardcode a patch number: it cannot be verified from this environment (no npm
access), and a stale invented version is worse than an explicit selection rule. **Task-level rule (must be
resolved before `pnpm install`):**

1. Target the **7.x** line (current major; v7 removed the Prettier dependency, so raw output is already
   stable/deterministic — v6 shelled out to Prettier, which would fight the drift gate).
2. Pick the newest 7.x release whose publish date is **≥ 8 days old** at task time:
   `npm view openapi-typescript time --json` (or `pnpm view`). `.npmrc` sets
   `minimum-release-age=10080` (7 days) — the extra day is slack against timezone/rounding.
3. **Do NOT add a `minimumReleaseAgeExclude` entry.** The only precedent in
   `pnpm-workspace.yaml` is security patches (`nanoid`, `js-yaml`); build tooling waiting a week is free.
4. Node 22 satisfies v7's engine floor (Node ≥ 20).
5. Confirm the `--immutable` flag exists in the pinned version (`openapi-typescript --help`) — see below.

### Determinism (why the diff gate does not produce false failures)

1. **Exact-pinned generator** + `pnpm install --frozen-lockfile` in CI.
2. **Deterministic input.** `apps/api/openapi.json` is already key-sorted and fixed-format by
   `emit-openapi.ts`, and guarded by `openapi:check`.
3. **Fixed flags.** The `generate` script is the only invocation; no ad-hoc flags anywhere.
4. **No formatter touches the output.** Add `packages/api-client/src/types.gen.ts` to `.prettierignore`
   (same rationale, same file, as the existing `apps/api/openapi.json` entry) and do **not** add a
   `packages/**` route to `.lintstagedrc.json`. If Prettier or `eslint --fix` reformatted the committed
   file, CI's raw regeneration would diff against it forever.

### `--immutable`

The hand-written DTOs are `readonly` on every field and use `ReadonlyArray`. `openapi-typescript`'s
`--immutable` reproduces that (`readonly` properties + `readonly T[]`), so adoption preserves the repo's
immutability discipline instead of quietly dropping it.

**Contingency if the flag is unavailable/renamed in the pinned version:** accept mutable generated types
and drop `readonly` at the alias layer. The risk is low and bounded — nothing in either app mutates a DTO;
`readonly → mutable` is a widening, so existing consumers keep compiling. Do **not** hand-roll a
`DeepReadonly<T>` helper in the alias layer (complexity for a non-problem, KISS).

## Drift gates in CI

### New path filter + fan-out

In `.github/workflows/ci.yml` `changes` job, add to `filters`:

```yaml
packages: ['packages/**']
```

and expose it as an output. Then:

| Job | New `if` condition |
|---|---|
| `api-client` (new) | `api == 'true' \|\| packages == 'true' \|\| shared == 'true'` |
| `web` | add `\|\| packages == 'true'` |
| `mobile` | add `\|\| packages == 'true'` |

`api` is in the api-client job's condition because a contract edit changes `apps/api/openapi.json` — the
gate's *input*. `shared` covers a lockfile/generator bump. Web and mobile must fan out on `packages` change
because that is precisely the mechanism the whole change exists to buy: **a backend contract edit
regenerates `types.gen.ts`, which trips the `packages` filter, which runs web + mobile `tsc --noEmit` and
turns a formerly-silent contract break into a red build.**

### The new job

```yaml
api-client:
  name: Typecheck & contract-drift (api-client)
  needs: changes
  if: ${{ needs.changes.outputs.api == 'true' || needs.changes.outputs.packages == 'true' || needs.changes.outputs.shared == 'true' }}
  steps:
    - checkout / pnpm / setup-node / pnpm install --frozen-lockfile
    - name: Regenerate contract types
      run: pnpm api-client generate
    - name: Fail if types.gen.ts is stale
      run: |
        git diff --exit-code -- packages/api-client/src/types.gen.ts \
          || { echo "::error::types.gen.ts is out of date. Run 'pnpm api-client generate' and commit."; exit 1; }
    - name: Typecheck api-client
      run: pnpm api-client typecheck   # also runs money-contract.assert.ts
```

Add `api-client` to `ci-success`'s `needs` list (the single stable required check).

**Why `git diff --exit-code` and not a `--check` script** (the `openapi:check` pattern): `openapi:check`
exists because the emitter is *our own* script and a `--check` mode is 5 lines there. Here the generator is
a third-party CLI that writes a file; wrapping it would mean authoring a check-mode shim (more code for the
same guarantee). Accepted tradeoff, to be documented for humans: **`pnpm api-client generate` must be run
on a clean-ish tree**, since the gate compares against git state rather than against an in-memory string.
In CI the tree is always clean.

### Interaction with `openapi:check` — chain of custody

The two gates are complementary and must both exist; neither subsumes the other:

| Gate | Proves | Job |
|---|---|---|
| `pnpm api openapi:check` | `openapi.json` still matches the Zod schemas | `api` |
| `git diff` on `types.gen.ts` | `types.gen.ts` still matches `openapi.json` | `api-client` (new) |
| `tsc --noEmit` (web / mobile) | both apps still match `types.gen.ts` | `web`, `mobile` |

Practical consequence for contributors: a PR that changes the HTTP contract now updates **two** committed
derived artifacts (`apps/api/openapi.json`, `packages/api-client/src/types.gen.ts`). Forgetting either is a
red build, never a silent drift. `contract:sync` does both in one command.

## Adoption mapping

### Web — `apps/web/src/api/types.ts` (238 lines, 14 interfaces + 1 type alias)

The file **stays** and becomes an alias/re-export barrel — its long "why" comments (money-as-string
discipline, the `esDemo`/`email` invariant, the pre-dedupe `totalFilasDatos` note, the US-004 widening
history) are knowledge that does not live in the OpenAPI descriptions and must not be deleted. Keeping the
file also means **zero consumer-file churn**: all 20+ importers keep `from './types'` / `from '@/api/types'`.

| Hand-written type | Target | Mismatch vs today | Policy |
|---|---|---|---|
| `BucketResumenDto` | `ResumenMesResponse['buckets'][number]` | `estadoSemaforo`: `string \| null` → `'verde'\|'amarillo'\|'rojo' \| null` (**narrower**) | Accept the narrowing — it is the contract truth. Fix any fixture/comparison typed as bare `string` locally |
| `ResumenMesDto` | `ResumenMesResponse` | none | direct alias |
| `ResumenAnualDto` | `ResumenAnualResponse` | none (`meses` `$ref`s the same schema — DRY preserved by the generator) | direct alias |
| `DetalleBucketTransaccionDto` | `DetalleBucketResponse['transacciones'][number]` | none | direct alias |
| `DetalleBucketDto` | `DetalleBucketResponse` | none | direct alias |
| `MeDto` | `AuthMeResponse` | none (`email: string \| null`, `esDemo` both already present) | direct alias |
| `ReclasificarCategoriaDto` | `TransaccionesCategoriaResponse` | none | direct alias |
| `TransaccionResponseDto` | `IngestaUploadResponse['transacciones'][number]` | none | direct alias |
| `IngestaResponseDto` | `IngestaUploadResponse` | none (`duplicadosOmitidos` already present) | direct alias |
| `IngestaListItemDto` | `IngestasListResponse['ingestas'][number]` | none (`estado` enum matches) | direct alias |
| `ApiVersionDto` | `VersionResponse` | none | direct alias |
| `AuthCapabilitiesDto` | `AuthCapabilitiesResponse` | **gains required `googleLoginMobileEnabled`** | Accept the wider type. `esAuthCapabilitiesDto` keeps checking only `googleLoginEnabled` — the repo's stated guard posture is "validate what the app consumes" (see the comment in `apps/mobile/src/api/post-ingesta.ts` — a mobile-side precedent, same posture); web never reads the mobile flag. Guard strength is a runtime decision, out of scope for a type substitution. Fixtures in `capabilities.test.tsx` need the extra field |
| `PreviewTransaccionDto` | `PreviewIngestaResponse['muestra'][number]` | none | direct alias |
| `PreviewIngestaDto` | `PreviewIngestaResponse` | none | direct alias |
| `EstadoIngestaResumen` (`'exitoso'\|'fallido'\|'pendiente'`) | — | **not on the wire** | **Stays hand-written.** It is a UI-level projection, not a DTO. Deleting or "generating" it would be wrong |

Cross-cutting mismatch classes and their standing policy:

- **Optionality.** Every adopted schema lists all its properties in `required`, so generated types have no
  unexpected `?`. If a future contract change makes a field optional, the resulting app-side error is the
  gate working as designed — fix the app, never patch the alias.
- **Nullability.** Already faithful in both directions (`banco: string | null`, `porcentajeBp: number | null`).
- **`readonly`.** Preserved via `--immutable` (see contingency above).
- **Narrowing (enums).** Generated string-literal unions are *stricter* than today's `string`. Compile errors
  land in fixtures and comparisons, and are fixed locally.

`src/domain/resumen.types.ts` living under `domain/` is a pre-existing naming wart (it is a DTO mirror, not
domain logic). **Do not move it** in this change — a rename would touch every mobile importer for zero
contract benefit (KISS; the review budget is better spent elsewhere).

### What explicitly does NOT change (assertable by inspecting the diff hunks)

- **web:** `client.ts` (~1026 lines) fetch wrappers and every guard (`esMontoStringValido`, `esFechaValida`,
  `esResumenMesDto`, `esDetalleBucketDto`, `esApiVersionDto`, …); the `ApiError`
  (`invalid|unauthorized|network|parse|server`) / `ApiResult` unions; `auth.ts` and `capabilities.ts` logic;
  all TanStack Query hooks; every component.
- **mobile:** `ApiError` (`unauthorized|network|parse|http`) / `ApiResult`; `copiaPorApiError`;
  `construirHeadersSesion`; `conTimeout` / `NETWORK_LEG_TIMEOUT_MS`; `session-store` / `session-context`;
  every fetch function and every guard; the local `PostIngestaError` / `PreviewIngestaError` unions.
- **backend:** nothing. `openapi:emit` / `openapi:check` / the Zod schemas are untouched.
- **error taxonomy reconciliation, `TokenStorage`, interceptors:** deferred with triggers (proposal
  non-goals table). This slice must not "sneak in" any of it.

Money safety is therefore *strictly additive*: the runtime guards remain the enforcement mechanism
(generated types are compile-time only — ADR-011's "sin validación runtime" still stands client-side), and
`money-contract.assert.ts` adds a compile-time pin on top:

```ts
type Assert<T extends true> = T;
type Eq<A, B> = (<T>() => T extends A ? 1 : 2) extends <T>() => T extends B ? 1 : 2 ? true : false;
export type _TotalIngresoIsString = Assert<Eq<ResumenMesDto['totalIngreso'], string>>;
export type _BucketTotalIsString  = Assert<Eq<BucketResumenDto['total'], string>>;
export type _CargoIsString        = Assert<Eq<DetalleBucketTransaccionDto['cargo'], string>>;
export type _AbonoIsString        = Assert<Eq<DetalleBucketTransaccionDto['abono'], string>>;
```

A backend change to `number` fails `pnpm api-client typecheck` in the new CI job. Exported aliases (not
locals) so `noUnusedLocals` never flags them. No test runner is added to the package — `tsc` is the gate
(YAGNI: Vitest returns when the package has runtime code to test).

## Mobile specifics

### `verbatimModuleSyntax: true`

Added to `apps/mobile/tsconfig.json` `compilerOptions`. It is the *erasure guarantee*: with it, `tsc`
rejects a value-position import of a type, so every `@moneydiary/api-client` import is provably
`import type` and is erased by Babel before Metro ever sees a module specifier. Web already runs with it
(`tsconfig.app.json`), so this also aligns the two apps.

**Risk to budget:** turning it on can surface pre-existing violations elsewhere in mobile (a type imported
without the `type` keyword). Mobile code already uses `import type` broadly, so expect few. **Contingency
if it cascades:** revert the flag and enforce the same rule with
`@typescript-eslint/consistent-type-imports` in mobile's ESLint config — weaker (lint vs. compiler) but it
keeps the slice small; record the flag as debt with the trigger "next time mobile's tsconfig is touched".

### The spike — what it verifies, and when

**Re-ordered vs. the proposal:** run the spike at the **start of the mobile slice, against the real package
already merged by slice 1**, not as a throwaway hello-world package first. Reasons: (a) a throwaway package
is strictly less informative than the real one (different `exports` map, different file), and (b) building
one costs a PR's worth of ceremony for a signal we get for free one slice later. The risk of finding out
late is bounded: mobile is the **last** slice and web does not depend on it, so a failure costs nothing
already shipped.

Three checks, in cost order (all local, none in CI):

1. **TS resolution:** `pnpm --filter @moneydiary/mobile exec tsc --noEmit` on a scratch file that does
   `import type { ResumenMesDto } from '@moneydiary/api-client'` and builds a fixture. Proves the pnpm
   symlink + `exports.types` map resolve under Expo's `moduleResolution`.
2. **jest-expo transform:** `pnpm --filter @moneydiary/mobile test` with that import present in a spec.
   Proves babel-preset-expo erases the type import and Jest's resolver is never asked for a runtime module.
3. **Metro bundle (the real unknown):** `npx expo export --platform android` inside `apps/mobile`. Headless,
   deterministic, exercises the full Metro graph over a pnpm-symlinked workspace dependency — the thing this
   repo has **zero precedent for**. A green export is the go signal.

**Expected finding:** nothing to configure (type imports are erased pre-bundle). **If (3) fails:** try
exactly one bounded remedy — `metro.config.js` monorepo defaults (`watchFolders` = workspace root,
`nodeModulesPaths`, `unstable_enableSymlinks`) — and time-box it. **If it still fails: stop.** Ship web-only
(slices 1-2 already merged and stand alone), mobile keeps its hand-written types, and the mobile adoption
becomes registered debt whose trigger is "Metro/Expo gains verified pnpm-symlink support (SDK bump)". That
fallback is exactly why the slices are split by app.

## ADR-012 amendment intent

**NOTE, not supersede.** The decision (a shared platform-agnostic `@moneydiary/api-client` fed by
`openapi.json`, `TokenStorage` by DI, no npm publication) is untouched; only two mechanics change, and the
note must say *why* so a future reader does not "restore" them. Spanish prose, matching the ADR's existing
style, appended as a dated note next to the 2026-08-02 one. Draft:

> **Nota 2026-08-XX (primer slice construido — mecánica ajustada):** el primer slice de este ADR se
> implementó como un `packages/api-client` **solo-tipos** (change SDD `api-client-package`): sin
> `client.ts`/`auth.ts`/`errors.ts` y **sin `tsup`**. Un paquete que no emite runtime no necesita build —
> `package.json` apunta `types`/`exports` al fuente TypeScript y cada consumidor lo compila; `tsup` existía
> para que Vite y Metro consumieran *código*, problema que este slice no tiene. Además, `src/types.gen.ts`
> **se commitea** (corrigiendo el `.gitignore` prescrito arriba): el archivo commiteado habilita el gate de
> drift `regenerar + git diff --exit-code`, espejo del `openapi:check` ya probado (ADR-011), y elimina un
> paso obligatorio de generación en cada clon y en cada job de CI. La fuente sigue siendo
> `apps/api/openapi.json`, no una copia dentro del paquete. `tsup` y el `.gitignore` original vuelven a
> evaluarse cuando aterrice el cliente runtime (interceptores + `TokenStorage` + `errors.ts`), que sigue
> siendo deuda registrada con gatillo: mobile como primer adoptante.

Design fixes the intent; `sdd-apply` writes the final prose. No other ADR changes (ADR-008 already
partially superseded by ADR-012; ADR-011 untouched).

## Slice sketch for `sdd-tasks` (Review Workload Forecast input)

Three PRs, chained, each independently revertible. Line estimates are **hand-written** lines changed;
generated/committed-artifact lines are called out separately because they are reviewed by *regenerating*,
not by reading (same convention as the committed `apps/api/openapi.json`; note
`routeTree.gen.ts` is NOT a precedent — it is gitignored/untracked).

| # | Slice | Contents | Hand-written Δ | Generated Δ |
|---|---|---|---|---|
| **1** | Package + CI foundation | `pnpm-workspace.yaml` (+`packages/*`), root scripts (`api-client`, `contract:sync`), `packages/api-client/{package.json,tsconfig.json}`, `src/index.ts` (alias layer), `src/money-contract.assert.ts`, `.prettierignore` entry, CI `packages` filter + new `api-client` job + `ci-success` needs + web/mobile `if` fan-out, lockfile | ~170 | `src/types.gen.ts` ~700-1000 |
| **2** | Web adoption | `apps/web/package.json` (`workspace:*` dep), `apps/web/src/api/types.ts` rewritten as an alias barrel (238 → ~90, comments preserved), fixture fixes in `capabilities.test.tsx` (+ any enum-narrowing fallout) | ~340 (≈240 del / ≈100 add) | — |
| **3** | Mobile adoption (spike first) | Metro/jest/tsc spike, `apps/mobile/tsconfig.json` (`verbatimModuleSyntax`), `apps/mobile/package.json` dep, `resumen.types.ts` + `client.ts` + `post-ingesta.ts` + `preview-ingesta.ts` aliasing, spec fixtures (`esDemo`, `duplicadosOmitidos`) | ~140 | — |

Plus the ADR-012 note (~15 lines of prose) — attach to slice 1, since that is where the mechanics land.

**Forecast call:** chained PRs recommended = **yes** (3). No single PR exceeds the 400-line hand-written
budget; slice 2 is the closest (~340) and is almost entirely mechanical deletion of retyped structure.
Slice 1's generated file is large but is a build artifact. Merging any two of these into one PR would
breach the budget — do not.

**Dependency order is strict:** 1 → 2, 1 → 3. 2 and 3 are independent of each other (that is the point:
mobile can be dropped without touching web). Slice 1 is mergeable on its own and is inert until adopted —
it adds a package nothing imports yet, which is the cheapest possible way to prove workspace + CI mechanics.

## Risks

| Risk | Mitigation / status |
|---|---|
| Metro cannot resolve a pnpm-symlinked workspace package | Types are erased pre-bundle (`verbatimModuleSyntax`); 3-step spike at the start of slice 3; bounded `metro.config.js` remedy; fallback = ship web-only, mobile debt with trigger |
| Chosen `openapi-typescript` version is inside the 7-day quarantine → install stalls | Explicit selection rule (newest 7.x with publish date ≥ 8 days) resolved at task time via `npm view`; no `minimumReleaseAgeExclude` entry (no precedent for tooling) |
| `--immutable` absent/renamed in the pinned version | Verify with `--help` in the first task; contingency = accept mutable types (widening, nothing mutates DTOs) |
| Non-deterministic emit → false drift failures | Exact pin + deterministic input + fixed flags + `.prettierignore` + no lint-staged route |
| `git diff --exit-code` gate is awkward on a dirty local tree | Documented; CI trees are always clean; `contract:sync` gives a one-command fix path |
| `verbatimModuleSyntax` surfaces pre-existing mobile violations | Expected small; contingency = ESLint `consistent-type-imports` and record the flag as debt |
| Enum narrowing (`estadoSemaforo`) breaks fixtures/comparisons typed as `string` | Compile-time, local, mechanical — this is the gate working; fix in the app, never in the alias layer |
| Adopting the wider `AuthCapabilitiesResponse` on web makes the guard weaker than the type | Accepted and documented: guards validate what the app consumes (existing repo posture); web never reads `googleLoginMobileEnabled`; guard strength is a runtime decision deferred to the client slice |
| Mobile `MeDto` gains `esDemo` / nullable `email` while `esMeDto` still demands a `string` email | Pre-existing runtime behavior, unchanged here; recorded as debt (demo accounts on mobile → `{tag:'parse'}`) |
| Alias layer drifts into a second hand-written mirror | Hard rule: every alias is a one-line indexed access; any mismatch is fixed in the app. Reviewable by inspecting `index.ts` alone |
| Slice 1's generated file inflates review perception | Declared a build artifact in the PR description; reviewed by regenerating (`pnpm api-client generate` + clean `git diff`), not by reading |
